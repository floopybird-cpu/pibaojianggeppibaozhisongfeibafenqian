# 实验草稿格式包

计算目标可用 components 声明多个结果分量。每个分量保存稳定标识、单位、含义和来源，计算页通过相同标识连接实际结果，组合目标的完整性逐分量核对。旧版单个目标继续直接使用自身标识。

数据处理请求以方法内的 equations 作为原式与变量定义的唯一详细记录，四阶段简述本阶段的知识、选材和诠释安排，通过关系名称接续到该记录。各点需要的解释程度由当前任务决定。操作时机、物理事件和分析选区各自保留真实含义。编页读取这个固定底稿和所选原件，完成后的可执行页保存到同一方法的新修订，界面由此生成。

数据处理草稿用可选的 `measurement_methods` 保存各独立配置及其顺序。每项含目标、实物读数和来源关系。承担计算的目标用稳定的标识对应结果；定性观察可在同页记述。后续补齐该方法的可执行 `page` 时，页面与原方案一起进入同一草稿修订。导出草稿时会显示哪些必交结果连到了实际输入，待核项保留具体原因。旧版草稿沿用原有四阶段结构。

实验开始实质工作前先保存 ExperimentDraft，之后的文稿和分析按其固定版本展开。它是贯穿同一实验的简要工作底稿，不是预习成品，也不是分节编写长文的临时缓存。新要求先补草稿，再写对应成果；已有草稿先读全文，沿原对象更新，不重新造一份互不衔接的提纲。

按逻辑顺序列出 prestudy（预习理解）、procedure（实施）、recording（记录整理）、analysis（分析解释），可以插入有用途的其他阶段。每点写：知识点 knowledge；选材与引用安排 material_plan；诠释要点 interpretations。knowledge.kind 区分 definition、fact、formula、procedure；诠释要回答为什么、如何联系或如何理解，不把定义换句话抄进去充数。程序从实际 interpretations 条目显示项数，无需再手填一个容易不同步的计数。

草稿不用写成详尽讲义，也不强求完整引文。material_plan 简述本点优先选哪份已知材料、选它的用途，以及是否需要补背景。sources 可为空；有确实取得的锚点再填写，不能猜ID和页码。后续正式稿的实际引用按各自格式要求完成。

记忆性命题也须选直接支持它的材料：优先已有可核实知识与原件；对术语冲突、范围过强或自己新增的命题，按需要查教材中的定义、条件或推导，不能挂一个同主题页号就当已证实。草稿可只记核实方向，不必展开全篇；后续本点被实际使用前完成必要核实。结构安排则说明前点如何提供后点所需的概念、读数或方法，不能靠四个阶段标题冒充逻辑已连通。

scope=overview 表示简要衔接，developed 表示本次重点。例如用户直接给数据要求分析：前面阶段按讲义简述实验模型、操作与读数关系即可；分析部分写清方法、输入、条件和解释安排。不为这项任务另查整部教材或先写完整预习。用户后来要求深入讲解某点，则先把该点知识、选材、诠释安排补入底稿，再展开正文。

底稿决定内容关系，不限定正式稿的章节顺序、篇幅或版式。发现撰写中确有新要求或合理的新认识，可以先有依据地更新底稿，再继续；不能在审计中拿着问题清单反复改底稿或成品以寻求本轮通过。

request 是宿主写入的真实用户要求与已答复事实，不由模型填写。submit_experiment_draft 保存并绑定当前任务；read_experiment_draft 可全文读取。后续文稿、程序自动带 draft_ref；draft_points 可以选择所用的真实要点，省略时按用途关联对应阶段。固定引用只证明生成依据可追查，不证明内容已经遵循或科学正确，这些仍须独立审计。

导出 draft.md 是人类可读草稿，draft.json 保留结构，原生窗口可直接阅读完整草稿。常规产物文件夹单列“实验草稿”；取走副本不影响内部历史。

## 跨实验范例

以下用单摆与电阻测量解释组织方法，属于教学示例，不是用户实验事实，不提供热导热电验收答案。完整范例在本包 examples.md，读取格式说明时一并返回。

新数据或实际答复推翻底稿前提时，应先据新证据订正底稿，再继续展开；不能改数据含义或只选择符合旧叙述的部分来维护底稿。底稿里的暂定假设不会因被写过一次就成为实测事实。相关规范表和真实答复是选材依据的一部分，未记录状态随任务保留；不要把这项制作规则抄成学生正文的免责段。


## 交付要求与实验知识分开

可选delivery_requests记录文件种类、语言、版式或正常修改要求，不把它们拆成实验知识点或诠释项。只调整现有成品版式时，读现有草稿，将新交付要求补入此列表即可，不重查原理、不为排版新造科学解释。原有实验阶段和事实依据保留。


## 讲义背景、确认与现场差异

先读已导入的对应讲义/说明，理解实验、仪器、流程和读数约定，再集中确认是否实际遵循以及有哪些差异。ask_user.material_basis记录实际出处锚点和适用原始记录；真实答复在material_background中跨任务接续，不能将已答复自动当同意。确认适用的背景可继承，差异就近覆盖，只问仍影响本任务的缺项。读数仍来自实测记录，混合笔记按实际实验分别对应。后台保存原答及引用身份，不要求学生填写内部ID。
